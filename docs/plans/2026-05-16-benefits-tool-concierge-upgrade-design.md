# Benefits Eligibility Tool — Concierge Upgrade Design

Date: 2026-05-16
Branch: `feature/benefits-tool`
Page: almacare.ca/benefits

## Goal

Shift the tool from "insurance intake form" to "guided postpartum care concierge." Same engine, same questions, same submission path — new framing, new copy, new visual rhythm. Families should leave feeling cared for, optimistic, and clear on what to do next, not like they just finished an insurance questionnaire.

## Information architecture

Five screens in a single-page flow:

1. **Landing** (new) — hero, service preview chips, "What Alma Care provides," disclaimer. Single CTA: *Begin assessment*.
2. **Step 1 — Personalize** — same questions, recopied headlines and microcopy.
3. **Step 2 — Coverage** — same questions, recopied.
4. **Step 3 — Services** — same questions, updated service labels and copy.
5. **Results** — restructured: personalized intro → ranked recommendations → HSA-eligible secondary section → what happens next → trust panel → emotional permission → final CTA + lead form → trust strip.

The landing screen lives in the same SPA shell as the steps — clicking *Begin assessment* hides it and reveals Step 1. The progress bar is hidden on the landing screen.

## Results page

### Ranked recommendations

Sort key in `computeResults()`:

```
1. covered_by_benefits desc  (true before false)
2. priority asc              (high=0, medium=1, low=2 — already in engine)
3. windowRank asc            (0 if state.weeksPostpartum falls inside dosing.window, else 1)
```

Display: top 3 as full numbered cards (number + label + one-line concierge rationale + dosing chip). Cards 4+ collapse into a *See additional recommendations* accordion to reduce decision fatigue.

Intro band above the cards:

> *You may have more support available to you than you think. Based on your responses, there appear to be several potential pathways to offset postpartum care through extended health benefits and/or HSA funding. We've outlined the options most relevant to your stage of recovery and care goals below.*

### HSA-eligible secondary section

Shown when ≥1 clinically-relevant rec is not in `state.coveredServices`. Heading: *Additional services that may be eligible through your HSA*. Body verbatim from brief. Bulleted examples: Private duty nursing, Nursing-led postpartum support, Lactation support provided by eligible practitioners, Select wellness and recovery services. Closes with *We recommend confirming practitioner eligibility directly with your benefits provider before booking care.*

Hides entirely when every recommended service is already covered.

### What happens next

Five-step numbered list (verbatim from brief): complete assessment → review recommendations → speak with specialist → build plan → begin care.

### We help families navigate the details

Capability panel, five bullets verbatim from brief.

### Support is not a luxury during postpartum recovery

Quieter visual treatment — soft cream background, no border, no card chrome — so it reads as a note rather than a UI element.

### Final CTA + lead form

*Review your options with an Alma Care specialist* + supporting copy. Existing lead form sits below.

### Trust strip

Three lightweight markers, no fabricated metrics:
- Trusted postpartum professionals
- Personalized practitioner matching
- Guided care coordination across Canada

## PDF cleanup

Three layers handle browser print-dialog chrome (date, URL, page numbers) which CSS cannot fully forbid:

**Layer 1 — `@page` margins to zero.** Chromium browsers omit default headers/footers when `@page` margin is `0`. Move the margin inside the print root as padding:

```css
@page { size: letter; margin: 0; }
#ap-print-root { padding: 0.6in 0.6in 0.75in 0.6in; }
```

**Layer 2 — Inline UX tip.** Muted helper text next to the print button: *Tip: in the print dialog, expand "More settings" and uncheck "Headers and footers" for a cleaner PDF.* Covers Firefox/Safari which still honor dialog settings.

**Layer 3 — Intentional printed content.**
- Set `document.title = 'Alma Care plan — ' + state.firstName` before `window.print()` so any leaked URL footer reads cleanly.
- Letterhead: Alma wordmark + *Care plan prepared for [name]* + date — single 2px green divider (already exists).
- Collapse the existing meta panel into the letterhead.
- Add a printed footer (`Alma Care — care@almacare.ca — almacare.ca/benefits`) so even if browser chrome slips through, our footer is the visual anchor.
- Tighten card padding 20px → 16px; remove background fills on `.ap-pdf__panel` (borders only) so the PDF reads as a document, not a UI screenshot.
- `page-break-inside: avoid` added to *What happens next* and *We help families navigate* blocks.

## Rollout

Production hosting:
- **Webflow** hosts the page shell and the head/body snippets pasted from `webflow-head.html` and `webflow-body.html`.
- **jsDelivr** serves `app.js` directly from this GitHub repo (`@main` pinned), because Webflow's Embed element caps at ~50K chars.

Deploy steps:
1. Merge `feature/benefits-tool` to `main` and push. jsDelivr picks up `app.js` within ~12h, or instantly with `?v=YYYYMMDD` appended to the script tag in `webflow-head.html`.
2. Paste the new `webflow-head.html` and `webflow-body.html` into Webflow and publish.

## Strategic principle

The page's purpose is not to "help users understand benefits." It is to make families feel cared for, guided, less overwhelmed, and confident taking the next step with Alma. Insurance navigation is the mechanism; the emotional experience is the product.
